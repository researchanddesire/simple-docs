## Verhalten in der aktuellen Dashboard/API-Quelle überprüft

– Die v2-Einstellungen API liefern Vorlagen als geordnete Segmente und erweitern konfigurierte Wiederholungen.
– Die v2-Kalibrierung API speichert die Kalibrierung pro Spielzeug für den Sitzungseigentümer.
– Die v2-Vervollständigung API akzeptiert Wiederholungs-, Ausdauer-, Freiform- und Sprungergebnisse.
– Die Vervollständigung API akzeptiert pass/fail-Daten und enthält eine Three-Strike-Verarbeitung.
– Das Dashboard stellt die Geräte-Avatar-Auswahl für berechtigte Konten und Firmware-Kanal-Steuerelemente für berechtigte Geräte bereit.
– Der Server löst die Firmware dynamisch auf, anstatt hier eine fest codierte Version zu veröffentlichen.

Diese Serverfunktionen beweisen nicht, dass jede Firmware-Version oder jedes Konto dieselbe Benutzeroberfläche erhält.

## Behauptungen, die hier unbestätigt bleiben

Das ausgecheckte Repository enthält nicht die Firmware DTT. Das genaue Verhalten der Offline-Warteschlange, die lokale Kapazität, das Wiederholungs-Timing, die Bildrate, die Bildschirme pro Version, die aktuellen Rollout-Prozentsätze und ein garantierter Rollback-Pfad können nicht überprüft werden. Siehe [Offline mode](/dtt/technical/offline-mode) für die konservative Persistenzgrenze.
