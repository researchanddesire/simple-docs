## State flow

| Order | State              | What to verify                                            | Recovery                                          |
| ----: | ------------------ | --------------------------------------------------------- | ------------------------------------------------- |
|     1 | Boot / welcome     | Trainer ID and startup text appear                        | charge, then restart if the display remains blank |
|     2 | Preflight          | pairing, connectivity, settings, and update checks finish | note the exact error; use the error center        |
|     3 | Settings fetch     | expected template and toy load                            | verify active template, pairing, and Wi-Fi        |
|     4 | Calibration        | both positions are accepted                               | use the calibration recovery table                |
|     5 | Session summary    | toy, mode, and segment are expected                       | stop and correct the dashboard selection          |
|     6 | Countdown          | mount is stable and you can move away                     | move away before motion if anything is wrong      |
|     7 | Active segment     | screen and LED/text feedback respond                      | stop movement and move away whenever needed       |
|     8 | Grade / pass state | completion or retry state appears                         | lower the template target if it is unsuitable     |
|     9 | Session complete   | completion is shown                                       | verify the result in the dashboard                |

## Offline branch

If online settings cannot load, some firmware can offer cached settings. The screen may warn that grades may not be saved. Treat that warning literally: continue only when the cached toy and session are correct, and assume no dashboard record until one appears.

## Update branch

An update screen may interrupt preflight. Keep the device powered and connected unless the screen reports failure or [Firmware updates](/dtt/technical/firmware-updates) instructs otherwise. Exact progress text and duration are firmware-specific.

## Pass/fail branch

When a template includes pass/fail behavior, the device can show a failed attempt and a retry count. Current server logic can process a three-strike result, but template behavior and firmware presentation can change. Follow the screen and stop if repeating the segment is no longer comfortable.

## Error branch

Use [Error codes and messages](/dtt/technical/error-codes). If the device freezes, stop the physical session, move away, power-cycle when safe, and record the screen before contacting support.
