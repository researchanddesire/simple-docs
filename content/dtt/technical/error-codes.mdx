## Calibration rejection

Current v2 server validation stores calibration only when the values remain within its 1.5–21.5 cm bounds and have at least a 2 cm gap. Those numbers are API validation bounds, not safety targets.

## Speed messages

During a segment, speed messages are feedback against the template. Never accelerate or deepen movement simply to clear a message when doing so is uncomfortable. Stop and edit the template instead.

If a speed error appears before motion begins or causes a repeating screen loop, record the firmware version if shown, connect online for the supported update path, restart once, and contact support if it repeats. This guide does not claim a particular firmware version fixes the loop because the firmware history is unavailable here.

## Failed attempts

The dashboard v2 API accepts a `passed` result and contains three-strike processing. The exact device wording and what a partner-configured template changes are version-dependent. A retry prompt is not an instruction to continue when you need to stop.

## Unlisted or repeating error

1. End the physical session and move away.
2. Photograph or copy the exact message.
3. Note the Trainer ID, selected toy, mode, network, and preceding action.
4. Power-cycle only after you are safely clear.
5. Email [support@researchanddesire.com](mailto:support@researchanddesire.com) if it repeats.
