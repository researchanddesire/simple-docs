## Setup and pairing

<Accordions type="multiple">
  <Accordion title="What is the recommended setup method?">

Use [automatic Bluetooth pairing](/lockbox/quick-start/pairing) in Chrome or Edge. It pairs the Lockbox and provisions 2.4 GHz Wi-Fi in one flow. Manual Wi-Fi setup is the fallback.

  </Accordion>
  <Accordion title="How do I pair a secondhand Lockbox?">

The previous owner should unpair it first. If that is impossible, contact [support@researchanddesire.com](https://www.researchanddesire.com/pages/contact-us) with proof of purchase and the identifier shown under **Settings → Pairing**. Do not publish the pairing code.

  </Accordion>
  <Accordion title="Why does the pairing code change?">

The code can change after a restart. Use the code currently shown on the device. Once paired, normal account ownership does not depend on retaining that code.

  </Accordion>
</Accordions>
## Roles and sessions

<Accordions type="multiple">
  <Accordion title="What are the Lockee and Keyholder roles?">

The **Lockee** is subject to the lock. A **Keyholder** is another account the Lockee authorizes to manage agreed session controls. Review consent, permissions, release, offline behavior, and revocation in the [Keyholder Guide](/lockbox/quick-start/keyholder-guide).

  </Accordion>
  <Accordion title="What is a self-lock?">

A self-lock is started without a Keyholder. Active self-lock controls can be more limited than a Keyholder-managed or test session, so complete a short test and verify Emergency Unlock before relying on it.

  </Accordion>
  <Accordion title="Can I add or remove a Keyholder during an active session?">

Do not change the partnership while a session is active. End the session safely, confirm the physical Lockbox is unlocked, then change the relationship under **Settings → Partners**. If account access or ownership is disputed, contact support.

  </Accordion>
  <Accordion title="What is a test lock?">

A test lock is a practice session intended to verify setup and release behavior before a real lock. Use [Start Your First Lock](/lockbox/quick-start/start-a-lock).

  </Accordion>
</Accordions>

## Power and connectivity

<Accordions type="multiple">
  <Accordion title="How long does the battery last?">

The existing product notes estimate about 24 hours unplugged under normal use, but actual runtime depends on screen, radio, motor, battery condition, and firmware behavior. Keep long sessions on stable power and verify the battery state before locking.

  </Accordion>
  <Accordion title="Should I keep the Lockbox plugged in?">

Use stable USB power for longer sessions when practical. The current documentation says a plugged-in Lockbox does not enter deep sleep, which helps preserve remote connectivity.

  </Accordion>
  <Accordion title="Why do the device and dashboard show different online states?">

The physical indicator is live; the dashboard can take up to 60 seconds to update. Compare them with [Check Online Status](/lockbox/support/online-status).

  </Accordion>
  <Accordion title="What works without Wi-Fi?">

Local timers, menus, and physical controls continue according to the state stored on the device. Remote Keyholder commands, dashboard changes, and public votes require connectivity. See the [Offline Capability Matrix](/lockbox/technical/offline-mode).

  </Accordion>
</Accordions>

## Features

<Accordions type="multiple">
  <Accordion title="How do scheduled breaks work?">

The session must enable breaks. The Lockee starts a break from the device, retrieves the key, and returns it before ending the break. Health and emergency access always take priority over an overdue record. See [Take a Break](/lockbox/using/take-a-break).

  </Accordion>
  <Accordion title="What does Hide Remaining Time hide?">

It hides countdown information from the Lockee-facing device and dashboard views described in the feature guide. It must not hide safety or emergency instructions. See [Hide Remaining Time](/lockbox/using/hiding-time).

  </Accordion>
  <Accordion title="What is Public Voting?">

It creates a shareable page where visitors can add or remove configured time. Agree on the audience and duration boundaries before sharing, and test how to disable it. See [Public Voting](/lockbox/using/public-voting).

  </Accordion>
  <Accordion title="What is Permalock?">

Permalock removes the preset end time and uses Keyholder-controlled release. It is an advanced online mode that requires completed test locks and reviewed emergency access. See [Permalock](/lockbox/device-states/permalock).

  </Accordion>
</Accordions>

## Emergency access

<Accordions type="multiple">
  <Accordion title="My Keyholder is unavailable and I need the key. What should I do?">

Use local [Software Emergency Unlock](/lockbox/device-states/emergency-unlock) when available. If it is disabled or the device cannot unlock, use [Hardware Backplate Emergency Access](/lockbox/support/emergency-backplate). Do not wait for support when access is urgent.

  </Accordion>
  <Accordion title="Can hardware emergency access be disabled?">

The current design uses a replaceable backplate as a destructive physical fallback. Software cannot disable that physical path. Review it before every long or remotely managed session.

  </Accordion>
  <Accordion title="What happens after software Emergency Unlock?">

The active session ends, the event may be shared with connected partners, and the current documentation describes a 24-hour cooldown before another lock. See [E-Lock 20](/lockbox/errors/e-lock-20). Safety comes before the cooldown or notification.

  </Accordion>
</Accordions>
