---
title: "Permalock (Lock Forever)"
description: "Understand Permalock responsibilities, preflight checks, release paths, and emergency access."
---

Permalock, also called **Lock Forever**, removes a preset end time and leaves normal release under Keyholder control. It is an advanced online session mode.

<Callout type="warn">

Do not use Permalock for a first session. Complete short self-lock and Keyholder-controlled test sessions first.

</Callout>

## Required preflight

- The Lockee and Keyholder have current, specific consent for this session.
- Both people completed the [Keyholder Guide](/lockbox/quick-start/keyholder-guide).
- The device is paired, online, charged, and has passed a short test lock.
- Both people confirmed normal, software-emergency, and hardware-emergency release paths.
- The Lockee can physically reach the Lockbox and emergency controls.
- There is an agreed urgent signal and a second communication channel.
- Both people agreed on health checks and when the session ends without debate.

## How release works

| Release path                                                         | Availability                                                                       |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Keyholder unlock                                                     | Normal release path while the Keyholder and device can communicate                 |
| Keyholder dashboard abandonment                                      | Available only where the current dashboard offers it; not a self-lock release path |
| [Software Emergency Unlock](/lockbox/device-states/emergency-unlock) | Local safety path when enabled for the session                                     |
| [Hardware backplate access](/lockbox/support/emergency-backplate)    | Destructive last resort if software access is unavailable                          |

Remote actions require connectivity. A Keyholder must not assume a dashboard command reached an offline or sleeping Lockbox; the Lockee should confirm the physical state.

## During the session

Maintain regular communication and health checks. End the session for pain, numbness, circulation changes, swelling, skin injury, panic, breathing difficulty, or any other concerning symptom. This documentation cannot determine whether a symptom is safe.

<Callout type="warn">

If software Emergency Unlock is disabled, hardware backplate access may be the only local fallback. Review that consequence before the session, not during an emergency.

</Callout>

## If anything differs from this guide

Dashboard options and firmware behavior can change. If a release control, connectivity state, or emergency option is not exactly as expected, do not begin the Permalock session. Contact [support@researchanddesire.com](mailto:support@researchanddesire.com).
